Clean layered architecture with event-driven pub/sub. Each service follows the Repository pattern with clear separation of concerns.

## Layer Responsibilities

| Layer | Owns | Must Not Own |
|-------|------|--------------|
| `server` | JSON helpers, request logging | Business logic, data access |
| Auth middleware | JWT validation, user injection | Business logic |
| API handlers (`src/apis`) | HTTP decode/validate/respond, routing | SQL, transactions |
| Services (`src/services`) | Business logic, orchestration | HTTP, SQL |
| Repositories | SQL, row mapping, transactions | HTTP, validation |
| `database` | `DB`/`Tx`/`Row` interfaces | SQL queries |
| `eventbus` | Pub/sub, handler registration | Business logic |
| `config` | Env loading, config structs | Business logic |

## Service Pattern

**Repository**  owns SQL, row mapping, transactions:

```go
type Repository interface {
    Create(ctx context.Context, input ProductInput) (Product, error)
    List(ctx context.Context, limit, offset int) (ListProductsResponse, error)
    Get(ctx context.Context, id int) (Product, error)
    Update(ctx context.Context, id int, input ProductInput) (Product, error)
    Delete(ctx context.Context, id int) error
}
```

**Service**  owns business logic, calls the repository. It knows nothing about HTTP:

```go
type Service struct {
    repo Repository
    bus  eventbus.Bus
}
```

**API handler (`src/apis`)**  thin HTTP adapter. It takes a narrow interface declared at the seam (never a `*Service` pointer), so handlers stay testable without a database:

```go
type Handler struct { svc Catalogue }

func (h *Handler) RegisterRoutes(mux *http.ServeMux) {
    mux.HandleFunc("POST /path", h.handler)
}
```

### Token Strategy

- **Access token**: HMAC-SHA256 JWT, 15-minute expiry, HttpOnly cookie
- **Refresh token**: 64-char hex, 7-day expiry, stored in DB + HttpOnly cookie
- No tokens in response body  all cookie-based

## Middleware Chain

Each route composes exactly the middleware it needs. The three wrappers are alternatives, not a chain:

| Middleware | Purpose |
|-----------|---------|
| `WithAuth` | Validates JWT from cookie/header, injects user into context |
| `WithAdmin` | Requires `role=admin` after `WithAuth` |
| `WithOptionalAuth` | Attaches user if present, proceeds unauthenticated if not |

For example, `POST /orders` uses `WithOptionalAuth` (guest checkout), `GET /orders` uses `WithAuth`, and `GET /admin/orders` uses `WithAuth(WithAdmin(...))`.

## Known Risks

- **D1 transactions not atomic**: the D1 HTTP API has no interactive transactions, so each statement executes immediately and `Rollback` only compensates the INSERTs it saw. A crash mid-commit leaves partial state.
- **In-memory event bus**: events are lost on process restart and handlers have no retries, so subscribers must be idempotent.
