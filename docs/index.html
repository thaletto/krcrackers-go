Overview

KR Crackers is a customer-facing e-commerce backend for a fireworks/crackers business. It handles product catalog, order lifecycle, payment proof uploads, PDF invoices, and WhatsApp notifications.

Key Features

Authentication
JWT + refresh tokens in HttpOnly cookies. Google ID token login. Role-based access (customer/admin).
Product Catalog
CRUD with search, filtering, sorting. Admin-only writes. Meilisearch-powered full-text search.
Order Lifecycle
Checkout with address snapshot. Status transitions: Pending → Confirmed → Shipped → Delivered.
Event-Driven
In-memory pub/sub decouples services. Product events sync search index. Order events trigger WhatsApp notifications.
File Uploads
Payment screenshots uploaded to Cloudflare R2 (S3-compatible). Customer-uploaded proof of payment.
PDF Invoices
On-demand PDF generation with sequential invoice numbers (INV-0001, INV-0002, ...). Stored on order record.

Architecture

Layered architecture with event-driven pub/sub for cross-service communication. Each service follows the Repository pattern with clean separation of concerns.

Request Flow

HTTP Request → main.go (Go 1.22+ method/path routing) → auth middleware (JWT validation, user injection) → service handler (decode JSON, validate, call repository) → repository (SQL, transactions via database.DB) → database adapter (SQLite or D1) ← domain struct → on mutation: publish event to eventbus.Bus → subscriber goroutines (search sync, notifications) ← HTTP Response (JSON)

Service Pattern

// Repository — owns SQL, row mapping, transactions
type Repository interface {
    Create(ctx context.Context, input ProductInput) (Product, error)
    List(ctx context.Context, limit, offset int) (ListProductsResponse, error)
    Get(ctx context.Context, id int) (Product, error)
    Update(ctx context.Context, id int, input ProductInput) (Product, error)
    Delete(ctx context.Context, id int) error
}

// Service — thin HTTP adapter, delegates to repository
type Service struct { repo Repository; bus eventbus.Bus }

func (s *Service) RegisterRoutes(mux *http.ServeMux) {
    mux.HandleFunc("POST /path", s.handler)
}

Authentication

JWT + refresh tokens stored in HttpOnly cookies. No tokens in response body. Google login validates ID tokens via JWKS.

Auth Flow

1. Client sends ID token to POST /auth/google 2. Server validates via Google JWKS (cached 6h) 3. Server creates/finds user by email 4. Server generates: - access_token cookie (15min, HMAC-SHA256) - refresh_token cookie (7d, random 64-char hex) 5. refresh_token stored in DB (refresh_tokens table) 6. On /auth/refresh: rotate refresh token, issue new access token 7. On /auth/logout: delete refresh token, clear cookies

Middleware

MiddlewareBehavior
WithAuthRequired. Returns 401 if no valid token.
WithAdminRequired + admin role. Returns 403 if not admin. Chain after WithAuth.
WithOptionalAuthAttaches user if present, proceeds unauthenticated otherwise.

In-memory pub/sub bus. Publishers fire events, subscribers handle them asynchronously in goroutines using context.Background().

Database

Same database.DB interface for both local SQLite and Cloudflare D1. Rows use typed accessors: row.Int(), row.String(), row.Float(), row.NullableString().

Dual Backend

Local SQLite
modernc.org/sqlite (pure-Go, no CGo). Real atomic transactions via *sql.Tx. Used in development.
Cloudflare D1
HTTP API via cloudflare-go/v7. Best-effort transactions (buffers on commit). Used in production.

Integrations

Meilisearch
Full-text product search with typo-tolerance, filtering, and sorting. Products synced via event bus.
Cloudflare R2
S3-compatible object storage for payment screenshots. Uses aws-sdk-go-v2.
WhatsApp Cloud API
Order lifecycle notifications via template messages. Noop fallback when unconfigured.
Google JWKS
ID token validation for Google login. Public keys cached for 6 hours.
